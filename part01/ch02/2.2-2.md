# Exercise 2.2-2

Consider sorting *n* numbers stored in array *A* by first finding the smallest element
of *A* and exchanging it with the element in *A*[0]. Then find the second-smallest
element of *A*, and exchange it with *A*[1]. Continue in this manner for the first *n* $-$ 1
elements of *A*. Write pseudocode for this algorithm, which is known as ***selection
sort***. What loop invariant does this algorithm maintain? Why does it need to run
for only the first *n* $-$  1 elements, rather than for all *n* elements? Give the best-case
and worst-case running times of selection sort in $\Theta$-notation.

# Answer

## Selection Sort $-$ Pseudocode

```java
public int[] selectionSort(int[] arr) {
    int n = arr.length;

    for (int i = 0; i < n - 1; i++) {
        int minIdx = i;

        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIdx]) {
                minIdx = j;
            }
        }
        int temp = arr[i];
        arr[i] = arr[minIdx];
        arr[minIdx] = temp;
    }
    return arr;
}
```

## Loop Invariant

**At the start of each iteration of the outer loop (index `i`), the subarray**

$$
arr[0 ... i - 1]
$$

**contains the smallest $i - 1$ elements of the array, sorted in increasing order.**

This loop invariant has three properties:

### Initialization:

Before the first iteration (i = 1), the subarray $arr[0...-1] is empty, which is trivially sorted.

### Maintenance:

Each iteration finds the smallest element in $arr[i...n]$ and swaps it into position $i$, thus extending the sorted
prefix to $arr[0...i]$

### Termination:

When the loop ends at $i = n$, the subarray $arr[0...n-1]$ is sorted and contains the smallest $n - 1$ values.

The final value automatically goes in the last position, so the whole array is sorted.

## Why does the algorithm run only for the first $n - 1$ elements?

Because once the first $n - 1$ elements are in sorted order:

- The last element **must** be the largest remaining element.
- There is no need to compare or swap anything.

If you ran the loop for $n$ iterations, the last iteration would do nothing.

So we stop early because the array is already sorted once the first $n - 1$ positions are correct.

## Running Time (Big $\Theta$)

### Inner loop runs:

$$
(n - 1) + (n - 2) + ... + 1 = \frac{(n - 1)n}{2} = \Theta(n^2)
$$

### Best-case:

Still must scan the entire unsorted portion at each step

&rarr; $\Theta(n^2)$

### Worst-case:

Same comparisons, only swap behavior changes

&rarr; $\Theta(n^2)$

So selection sort always takes:

$$\boxed{
\Theta(n^2)
}$$

regardless of input order.
