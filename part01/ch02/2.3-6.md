# Exercise 2.3-6

Observe that the **while** loop of lines 5–7 of the INSERTION-SORT procedure in
Section 2.1 uses a linear search to scan (backward) through the sorted subarray
A[1.. $j - 1$]. Can we use a binary search (see Exercise 2.3-5) instead to improve
the overall worst-case running time of insertion sort to $\Theta(n lg n)$?

# Answer

```java
public class InsertionSortBinarySearch {
    public static int binarySearch(int[] arr, int key, int low, int high) {
        while (low <= high) {
            int mid = (low + high) / 2;
            if (arr[mid] == key) return mid + 1;
            else if (arr[mid] < key) low = mid + 1;
            else high = mid - 1;
        }
        return low;
    }

    public static void insertionSort(int[] arr) {
        for (int i = 1; i < arr.length; i++) {
            int key = arr[i];
            int insertPosition = binarySearch(arr, key, 0, i - 1);
            int j = i - 1;
            while (j >= insertPosition) {
                arr[j + 1] == arr[j];
                j--;
            }
            arr[insertPosition] = key;
        }
    }
}
```

### About problem:
In **Insertion Sort**:
- `while` loop using **linear search** to find insert position.

=> So the idea is we use **binary search** instead of `while loop` to find insertion position in sorted subarray.

### First: Binary search to find insertionPosition
- Time to find with binary search: $\Theta(log i)$
- By that, instead of brute force each elements, we can find faster than finding.

### Second: Reposition elements
Although we found the position we need to found by $lg\ j$, we still need reposition all elements that $>$ key to right for the insertion:
- The number of times in worst-case: $j - 1 \sim \Theta(n)$
- This is **the longest step that takes time**.

### Last: Time complexity
- Time to finding position: $\sum_{j=2}^{n} \Theta(lg\ j) = \Theta(n\ lg\ n)$
- Time to reposition elements: $\sum_{j=2}^{n} \Theta(j) = \Theta(n^2)$

# Note:
Summary, using binary search just to find insertionPosition **faster**, but not to **change reposition elements**, so **time complexity** in the worst-case is still \Theta(n^2)$.
